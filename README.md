# VOID Blog

Authoring notes for writing posts and images. This text was generated by LLM.

## Write a Post (Markdown)

Recommended: use the helper to scaffold a post interactively.

- Run: `bun run new`
- Prompts for header, slug (defaults from header), subheader, and tags.
- Creates: `posts/<YEAR>/<index>_<slug>.md` with `date: draft` and a starter body.
- Tries to open the file in VS Code if `code` is available.

Manual (optional): create a file under `posts/<YEAR>/<something>.md`. Start with a metadata block (key: value, one per line), then a blank line, then the content.

Example:

```
slug: chatgpt-ir-pico-mokymasis
header: ChatGPT ir Pico mokymasis
subheader: Kaip AI padėjo mokantis Pico
date: 2025-09-16
tags: electronics, pico, chatgpt

# Intro

Sveiki atvykę…

![Oscilloscope result](images/test_result_osci.avif "small")

Ir dar tekstas…
```

Fields:
- `slug`: URL slug used for the post (`/<year>/<slug>`)
- `header`: Post title, shown in list and detail
- `subheader`: Subtitle under the title
- `date`: ISO date `YYYY-MM-DD` (used for sorting and canonical year), or `draft` to keep the post unpublished (excluded from the build)
- `tags`: Comma-separated list (optional)

The builder strips the metadata header automatically and renders the rest via Markdown.

## Drafts

- You can keep a post as a draft by setting `date: draft` in the metadata.
- Drafts are omitted from `dist/posts.json` and no `dist/<YEAR>/<slug>.html` is generated.
- To publish, change `date` to the desired `YYYY-MM-DD` and rebuild.

## Images, Captions, and Sizing

Where to put images:
- Place files in `posts/<YEAR>/images/` and reference them as `images/<name>.<ext>` in Markdown.
- The build copies them to `dist/images/<YEAR>/` and rewrites the `src` to `/images/<YEAR>/<name>.<ext>`.

Captions:
- If an image is the only thing in a paragraph and has alt text, the renderer wraps it in `<figure>` and uses the alt text as `<figcaption>`.
  - Example: `![Oscilloscope result](images/example.avif)` → `<figure><img …><figcaption>Oscilloscope result</figcaption></figure>`

Half-size (small) images:
- Use the image title to hint size:
  - `"small"` or `"half"` → 50% width, centered
  - `"w=NN%"` → set a percentage width, centered (e.g., `"w=40%"`)
  - `"width=NNpx"` or `"w=NNpx"` → set pixel width, centered (e.g., `"width=300px"`)

Examples:
- Half width: `![](images/scope.avif "small")`
- 40% width: `![](images/scope.avif "w=40%")`
- 300px width: `![](images/scope.avif "width=300px")`

Notes:
- Alt text is used for figcaptions; leave it empty if you don’t want a caption.
- All images are centered in the article; default width is 100%.

## WebM Videos (image-like)

You can embed a local `.webm` using the same Markdown image syntax, and the builder will render a `<video>` tag with:
- `autoplay loop muted playsinline`
- the same sizing hints as images (`"small"`, `"w=NN%"`, `"width=NNpx"`)
- the same figure/caption behavior (alt text becomes `<figcaption>` when implicit figures apply)

Autoplay control:
- Default is `autoplay`.
- Add `"noautoplay"` (or `"manual"`) to disable autoplay (this also enables `controls`).
- Add `"controls"` to show controls (with or without autoplay).

Examples:
- `![fkn windos](images/fkn_win_arrows.webm "small")`
- `![manual play](images/demo.webm "small noautoplay")`
- `![](images/demo.webm "w=60%")`

## YouTube Embeds (image-like)

You can embed a YouTube video using the same Markdown image syntax, and the builder will render a responsive `<iframe>` with the same sizing rules and figure caption behavior:

- Use a YouTube URL as the image source:
  - `![](https://www.youtube.com/watch?v=VIDEO_ID)`
  - `![](https://youtu.be/VIDEO_ID)`
  - Shorts are supported: `![](https://www.youtube.com/shorts/VIDEO_ID)`
- Optional size hints in the title work the same way:
  - Half width: `![](https://youtu.be/VIDEO_ID "small")`
  - Custom width: `![](https://youtu.be/VIDEO_ID "w=60%")`
- Provide alt text to show a caption under the video:
  - `![Demo clip](https://youtu.be/VIDEO_ID)` → figure with caption “Demo clip”
- Start time is respected from `t` or `start` query, e.g. `?t=90` or `?t=1m30s`.

## Architecture

Build-time
- scripts/build-posts.js
  - Scans `posts/<YEAR>/*.md`.
  - Parses the front‑matter style metadata block (slug, header, subheader, date, tags).
  - Renders the Markdown body to HTML using markdown-it + implicit figures for captions.
  - Rewrites image paths `images/...` to `/images/<YEAR>/...` and copies source files to `dist/images/<YEAR>/`.
  - Interprets simple size hints in image titles: `small`/`half` (50%), `w=NN%`, `width=NNpx`.
  - Outputs one HTML file per post: `dist/<YEAR>/<slug>.html` and a manifest `dist/posts.json`.
- scripts/copy-html.js
  - Copies `src/blog.html` to `dist/blog.html`.
  - If `posts.json` exists, replaces the list view section with the rendered list (links include `data-post` slugs).
- Bundling
  - `bun run build` bundles `src/main.js` into `dist/bundle.js` and minifies `src/blog.css` to `dist/blog.css`.

Runtime (client)
- src/main.js
  - Housekeeping: clears post HTML caches in `localStorage` every 24h (keeps theme).
  - Localhost: when served from `localhost`/`127.0.0.1`/`::1`, clears all `localStorage` on load regardless of TTL.
  - Initializes theme, router, header sizing, glitch effect, and list event handlers (hover/focus preload; opens on plain left mousedown; ctrl/cmd/middle-click use browser default; right-click ignored).
  - Preload behavior: hovering or focusing a post link preloads its HTML into `localStorage` so clicking opens instantly.
- src/router.js
  - Handles navigation on `popstate` and initial load. Accepts `/slug` or `/YEAR/slug` and canonicalizes to `/YEAR/slug`.
  - Validates the slug exists in the list; unknown or mismatched YEAR routes back to `/`.
- src/posts.js
  - `preloadPost(id, meta)`: creates a hidden article shell, loads HTML from `localStorage` or fetches `/YEAR/<slug>.html`, then caches it.
  - `openPost(id, push, link, meta)`: pushes canonical URL, swaps list→detail with View Transitions, and shows the requested article.
  - `closePost(push)`: returns to list with a View Transition and updates history.
  - Caching: post HTML is stored in `localStorage` under the slug key.
  
- src/theme.js + src/viewTransition.js
  - Theme switch uses View Transitions when available (fallback: brief CSS color transition).
- src/blog.css
  - Defines light/dark tokens, layout, transitions, image centering, figure captions, and “small/half” image sizing.
